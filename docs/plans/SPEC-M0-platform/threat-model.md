## Threat model SPEC-M0-platform

Phạm vi: khung local tối thiểu (SPEC-M0 mục 4). Chỉ chạy trên máy dev, dữ liệu là dữ liệu dev, không auth, không contracts, không gọi LLM.
Các hạng mục đã hoãn ở SPEC mục 10 (TLS, Nginx, Squid, Docker secrets, CI, image production) **không** được đưa thành SR.

Tác nhân đe dọa thực tế ở M0:
- (A1) Máy khác cùng mạng LAN/Wi-Fi với máy dev.
- (A2) Trang web độc hại mà dev mở trên cùng trình duyệt, gửi request tới `localhost`/`127.0.0.1` (drive-by localhost, DNS rebinding).
- (A3) Gói phụ thuộc hoặc image bị lỗi/độc hại (chuỗi cung ứng).
- (A4) Rò rỉ do chính dev hoặc coding agent: log, lỗi, output terminal bị dán vào PR, issue, transcript agent; secret lọt vào git.

### Luồng dữ liệu bị ảnh hưởng
- F1. Trình duyệt (origin `http://localhost:3000`) → `GET http://127.0.0.1:8080/healthz` (CORS) → JSON → trang chủ render trạng thái. Ranh giới tin cậy: origin web ↔ API; mọi trang web khác trong trình duyệt cũng gửi được request tới cổng này (A2).
- F2. Mạng LAN → cổng host 3000 (next dev), 8080 (API), 5432 (Postgres), 6379 (Redis). Ranh giới: máy dev ↔ LAN (A1). Docker trên Linux bỏ qua ufw khi publish cổng `0.0.0.0`.
- F3. `.env` gốc repo → config Go (env) / Python (pydantic-settings) → log JSON, stderr khi lỗi config, output `make`. Ranh giới: secret → kênh log/terminal mà agent và người đọc được (A4).
- F4. Go API → Postgres/Redis (ping trong `/readyz`) → kết quả → body 503 trả client. Ranh giới: chi tiết lỗi nội bộ → client không tin cậy (A2).
- F5. Request HTTP bất kỳ (header `X-Request-ID`, query, `Authorization`, `Cookie`) → middleware request id / access log / recover → log và response header. Ranh giới: input client → log.
- F6. Worker → Redis (M0-T07) với URL có mật khẩu → log.
- F7. npm, PyPI, Go proxy, Docker Hub, mise → máy dev (lockfile, image, toolchain). Ranh giới: chuỗi cung ứng (A3).

### Cần Owner xác nhận
1. **Go 1.23**: Go 1.23 đã hết hỗ trợ từ 08/2025. govulncheck sẽ báo lỗ hổng stdlib (`net/http`, `crypto/*`) chỉ được vá ở bản mới hơn, nên AC6.2 (`make sec` xanh) khó đạt. Đề xuất: giữ `go 1.23` trong `go.mod` làm mức tối thiểu (khớp `docs/Kiến trúc.md` mục 2), nhưng `mise.toml` và dòng `toolchain` pin bản Go đang được hỗ trợ; hoặc sửa SPEC.
2. **Redis 7.2**: phải pin bản vá ≥ 7.2.11 (CVE-2025-49844). Lúc cài cần kiểm lại vòng đời của nhánh 7.2; nếu đã hết hỗ trợ thì Owner chọn nhánh khác.
3. **`make sec` thiếu semgrep và trivy fs** so với skill `security-standards` mục 2 (AC6.2 chỉ có 4 công cụ). Chấp nhận cho M0, bù một phần bằng SR-19; thêm hai công cụ này khi có CI.

### Ghi chú cho module sau
- M1 (cookie refresh): CORS phải giữ allowlist của SR-12 khi bật `Allow-Credentials`; bổ sung kiểm `Origin` cho endpoint dùng cookie (T10), và cân nhắc kiểm `Host` để chống DNS rebinding.
- M4/M6 (SSE): đừng tắt `WriteTimeout` toàn cục (SR-13); nới riêng cho route SSE bằng `http.ResponseController`.
- M1/M3: secret chuyển sang Docker secrets dạng file; tiếp tục dùng kiểu che secret của SR-6/SR-7; key của provider không bao giờ đi qua env, càng không qua `NEXT_PUBLIC_*`.
- M3/M4: request id truyền vào job Redis và trace phải được kiểm lại theo regex của SR-11 ở phía worker; gọi provider thật bắt buộc qua Squid trước.
- Khi có Nginx: thêm CSP và các security header cho web (T9); tới lúc đó SR-15 mới có lớp phòng thủ thứ hai.
